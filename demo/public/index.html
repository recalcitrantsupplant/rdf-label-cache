Labels for your RDF, served from a CDN.

Every RDF app resolves IRI → label endlessly - for predicates, classes and entities. Do it once from a globally edge-cached CDN: rdfs:label, skos:prefLabel, schema:name and your own IRIs, resolved at the edge and never from your triplestore.

Deploy your own

Two paths — both end with your labels in your own R2 bucket. It ships empty; you populate R2 once with your own IRIs and any ontologies you reference (Schema.org, DCAT etc.)

Get started fast

No clone, no local Node — deploy from the browser, seed from a GitHub Action. Best for vocabularies & small/modest label sets.

1

The button provisions the Worker + R2 bucket and clones the repo into your GitHub.

2

Add credentials

Set SEED_BASE + R2_BUCKET and the R2 / purge secrets on the repo.

3

Add labels

Drop RDF into the labels/ folder and commit.

4

Run the seed

Actions → seed-labels → Run workflow. Optionally tick “include common ontology labels”.

Larger datasets

Clone + pipeline, on your machine or your own CI. Best for large label sets, frequent refreshes & full control.

1

Clone & install

git clone https://github.com/recalcitrantsupplant/rdf-label-cache && just install
2

Dump annotation properties

One SPARQL CONSTRUCT → labels + descriptions for every IRI your data mentions.

3

Cloudflare & credentials

Create the R2 bucket, deploy the Worker, make an R2 API token.

4

Generate & upload

just project=<you> ingest upload

The fast path uploads through GitHub Actions — for small/modest RDF, and re-running is an upsert, not a mirror. For large label sets, or more robust synchronisation than a GitHub Action, use the clone + pipeline path.
