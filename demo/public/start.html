Getting started

Cache the labels your app needs — your own IRIs plus the public-vocabulary terms your data uses — in five steps. Nothing ships pre-loaded; you populate R2 once.

Commands:

Configuration

Put these in .env (copy .env.example) or export them in your shell — the deploy and seed steps read them:

SEED_BASE
Your deployed Worker URL, e.g. https://<worker>.workers.dev — printed by wrangler deploy (step 3).
R2_ACCOUNT_ID
Your Cloudflare account id — right sidebar of the dashboard, or run wrangler whoami.
R2_ACCESS_KEY_ID
R2_SECRET_ACCESS_KEY
An R2 API token: dashboard → R2 → Manage API Tokens → Create API Token with Object Read & Write. The secret is shown only once.
SPARQL_ENDPOINT (optional)
Your triplestore's query endpoint — used by just bootstrap / just extract-labels to pull the labels.

With .env filled in, run the whole flow at once with just bootstrap (or pass an endpoint to override SPARQL_ENDPOINT: just bootstrap https://other/sparql) — or follow the steps below individually.

1

Clone & install

git clone https://github.com/recalcitrantsupplant/label-cdn && cd label-cdn
pnpm install
2

Dump the annotation properties you want cached

From your triplestore, CONSTRUCT the labels and descriptions for every IRI your data uses — your own entities and the public-vocabulary terms they reference — and save it as data.ttl:

just extract-labels https://your-endpoint/sparql   # runs the query below → data.ttl

This runs the SPARQL query below — it's only a starting point. Write your own or adapt it to cache whatever you need: despite the name, nothing in label-cache is hardcoded to labels. It stores and serves whatever triples you give it, keyed by IRI — labels are just the common case.

PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>
PREFIX skos: <http://www.w3.org/2004/02/skos/core#>
PREFIX dcterms: <http://purl.org/dc/terms/>
PREFIX schema: <https://schema.org/>
CONSTRUCT { ?iri rdfs:label ?l ; rdfs:comment ?c ; skos:prefLabel ?p ; skos:definition ?d ;
            dcterms:title ?t ; dcterms:description ?desc ; schema:name ?n }
WHERE {
  { SELECT DISTINCT ?iri WHERE {
      { ?iri ?px ?ox } UNION { ?sx ?iri ?ox } UNION { ?sx ?px ?iri FILTER(isIRI(?iri)) } } }
  OPTIONAL { ?iri rdfs:label ?l }     OPTIONAL { ?iri rdfs:comment ?c }
  OPTIONAL { ?iri skos:prefLabel ?p } OPTIONAL { ?iri skos:definition ?d }
  OPTIONAL { ?iri dcterms:title ?t }  OPTIONAL { ?iri dcterms:description ?desc }
  OPTIONAL { ?iri schema:name ?n }
  FILTER(BOUND(?l)||BOUND(?c)||BOUND(?p)||BOUND(?d)||BOUND(?t)||BOUND(?desc)||BOUND(?n))
}
curl -sf https://your-endpoint/sparql \
  --data-urlencode query@query.rq \
  -H 'Accept: text/turtle' -o data.ttl

Any RDF file works — no triplestore needed for small data. Want whole public vocabularies instead of just what you use? Run pnpm seed:ingest with no --input.

3

Set up Cloudflare

pnpm wrangler r2 bucket create rdf-public-labels
pnpm wrangler deploy                 # prints your Worker URL
just bucket     # create the R2 bucket (one-time)
just deploy     # prints your Worker URL

No namespace registration. The Worker keys R2 by the full IRI (labels/https://schema.org/name/en), so any namespace resolves once its labels are uploaded — and keys stay browsable in R2 for debugging.

Then create an R2 API token (dashboard → R2 → Manage API Tokens) for the upload.

4

Generate & upload your label objects

export SEED_BASE=https://<your-worker>.workers.dev
export R2_ACCOUNT_ID=... R2_ACCESS_KEY_ID=... R2_SECRET_ACCESS_KEY=...
node scripts/ingest.mjs --input data.ttl    # → dist/seed/manifest.ndjson
node scripts/upload-seed.mjs                 # → R2, over the S3 API
# SEED_BASE + R2_* come from your .env (see .env.example)
just ingest    # → dist/seed/manifest.ndjson
just upload    # → R2, over the S3 API

ingest warns about any IRIs whose namespace you haven't registered in step 3.

Customize the JSON-LD context — optional: your own vocabularies

Each object's keys (prefLabel, definition, …) are JSON-LD terms, not baked-in fields — they're defined by the shared @context served at SEED_BASE/context/labels-v1.json, which is what tells a consumer that prefLabel expands to skos:prefLabel. To use your own vocabularies, edit that context. It's generated from the CONTEXT_DOC object in scripts/ingest.mjs, then re-uploaded by just upload.

Add a namespace prefix & term

So consumers can expand your keys. Inside CONTEXT_DOC["@context"]:

ex: "https://example.org/vocab#",
displayName: { "@id": "ex:displayName", "@container": "@language" },

A bare prefix does nothing on its own — the stored objects use full-IRI @ids. A prefix only matters once it defines a term like displayName above.

Also cache a new annotation property

To actually populate that key from your data, add its predicate IRI to LABEL_PREDS or DESC_PREDS in scripts/ingest.mjs so ingest picks it up.

Then re-run just ingest && just upload. (If you also use the local smoke test, mirror the change in src/routes/dev-seed.ts's CONTEXT_DOC.)

5

Consume from your app

const labels = Object.fromEntries(await Promise.all(
  iris.map(async (iri) => {
    const res = await fetch(`${BASE}/label?iri=${encodeURIComponent(iri)}&lang=en`);
    return [iri, res.ok ? (await res.json()).prefLabel?.en : null];
  }),
));

Fire them concurrently — never one-at-a-time. See the FAQ on why one-request-per-label is fine over modern HTTP.
